# 源码注释规范

## 目标

注释用于记录业务约束、状态可信度、兼容原因和不明显的实现选择，让后续版本能够
安全修改。注释应简洁，不复述一眼就能读懂的代码。

## 语言与格式

- 用户文档、界面文本和业务注释使用简体中文。
- 类型、方法、参数和协议字段继续使用清晰英文命名。
- 面向多个项目使用的公共协议类型和重要公共服务使用 `/// <summary>` XML 注释。
- 方法内部只在并发、持久化、兼容、状态验证或系统调用等关键位置使用 `//` 行注释。
- 每条注释说明“为什么这样做”或“必须保持什么条件”，避免只描述“代码正在做什么”。

## 必须说明的内容

1. 协议版本与旧版兼容边界。
2. 命令从已发送到已验证的阶段含义。
3. 在线状态、显示状态和状态是否已验证之间的区别。
4. 同一设备新旧连接并存时的处理规则。
5. 数据文件的保存位置、上限和原子替换方式。
6. Windows 电源、黑幕窗口、像素检测和紧急退出等平台相关行为。
7. 任何暂时保留的兼容入口及其关闭前提。

## 不应添加注释的内容

- 自动生成的 `*.Designer.cs` 控件布局。
- 发布目录中的编译产物、第三方运行时和压缩后的网页资源。
- 单纯赋值、明显的空值判断或清晰的 LINQ 表达式。
- 已经失效的历史实现；历史信息放入版本说明或 Git 记录。
- 无法证实的旧版本行为。未验证内容必须明确写“待实机验证”。

## 示例

```csharp
/// <summary>
/// 保存 Agent 心跳，并只接受与当前连接绑定的设备编号。
/// </summary>
public DeviceView UpdateHeartbeat(...)
{
    // 防止一个连接伪造另一台设备的状态。
}
```

```csharp
// 先写临时文件再替换正式文件，避免进程中断留下半个 JSON。
File.Replace(tempPath, dataPath, null);
```

## 修改检查

- 注释和代码行为一致。
- 没有把“命令已发送”写成“屏幕已完成操作”。
- 没有声称 Android V1.5 或 Windows V15 已完成未经实机验证的兼容性。
- Release 构建仍保持 0 个错误、0 个警告。
